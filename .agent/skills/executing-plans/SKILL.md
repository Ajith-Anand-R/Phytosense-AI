# Executing Plans Protocol

## Overview

Load an implementation plan generated by `@writing-plans`, review it critically, execute tasks in controlled batches, and verify each step thoroughly before moving forward.

**Core Principle:** Batch execution with rigorous verification gates.  
**Announce at start:**
> "I'm using the `@executing-plans` skill to execute this plan task-by-task."

---

## Execution Steps

### Step 1: Load and Review the Plan
1. Read the plan document at `docs/plans/YYYY-MM-DD-<feature-name>.md`.
2. Inspect `docs/plans/task.md` to determine current progress.
3. Review tasks critically. If any step is ambiguous or has outdated assumptions, raise questions with the user before touching files.

### Step 2: Batch Execution (Default: 1–3 Tasks)
For each task in the active batch:
1. Mark the task as `in_progress` in `docs/plans/task.md`.
2. **Follow every sub-step exactly:**
   - Write the failing test.
   - Run the test to confirm failure.
   - Implement the minimal code.
   - Run the test to confirm it passes.
   - Run linter/formatting if applicable.
3. Mark task as `completed` in `docs/plans/task.md`.

### Step 3: Batch Verification & Report
When the batch is finished:
- Present a concise diff/status summary.
- Show test execution results.
- Ask: "Batch verified. Ready to proceed with the next batch?"

### Step 4: Stop-and-Ask Conditions
**HALT execution immediately and consult the user if:**
- A test fails unexpectedly and doesn't resolve within one attempt.
- A missing dependency, hidden assumption, or breaking interface is uncovered.
- The plan lacks instructions for an edge case encountered during coding.

### Step 5: Final Completion Verification
When all tasks are marked complete:
- Run the full project test suite.
- Verify documentation matches the final implementation.
- Commit all remaining changes with a clean git status.
